# OIDC Publish Doctor v0.1.0-beta.1

First public beta of the GitHub Action for diagnosing npm Trusted Publishing
configuration before `npm publish`.

## Included

- GitHub OIDC token acquisition and local inspection of selected identity claims.
- Pure, testable rules for Node/npm versions, GitHub-hosted runners, expected
  publisher owner/repository/workflow/environment, reusable workflows, package
  repository metadata, monorepo directories, and npm authentication indicators.
- Compact console report, GitHub Job Summary, annotations, and JSON diagnostics
  through the `issues` output.
- Secret-safe diagnostics: tokens, npmrc credential values, JWTs, command stderr,
  and exception details are not reported.
- A committed Node 24 bundle in `dist/`, CI validation, runner smoke test, and an
  end-to-end sandbox workflow.

## Beta boundaries

- `pass` is a local preflight result. It does not verify the Trusted Publisher
  settings saved on npm, allowed publishing actions, package ownership, or npm's
  OIDC token exchange.
- Registry intent (`REG001`), legacy setup-node detection (`AUTH003`), and an
  explicit expected-absent environment (`ENV002`) are not implemented.
- Use an exact tag: `albertofcasuso/oidc-publish-doctor@v0.1.0-beta.1`.

## Validation

- 42 unit tests pass.
- Lint, formatting, typecheck, bundling, bundle freshness, and standalone bundle
  smoke test pass.
- GitHub-hosted OIDC acquisition was verified in this repository's workflow.

## Feedback

Please report the workflow shape, Node/npm versions, sanitized diagnostic JSON, and
whether a diagnosis was useful. Do not include npm tokens, GitHub request tokens,
